# Кошик, оформлення замовлення та адмінка замовлень

Дата: 2026-08-27
Статус: затверджено, готово до планування реалізації

## Мета

Зараз кнопка "Купити" на картці товару (шини/диски) відкриває Telegram-чат із власником з
прешовненим текстом. Потрібно замінити це на повноцінний кошик з оформленням замовлення:
покупець набирає кілька товарів з обох каталогів в один кошик, заповнює контактні дані й спосіб
доставки, після чого замовлення одночасно потрапляє в Google Таблицю власника (як довготривале
джерело правди) і дублюється повідомленням від Telegram-бота "Tire Place" в чат власника.
Власник бачить і опрацьовує замовлення в новій вкладці існуючої адмінки `/admin`.

## Поза межами (non-goals)

- Без онлайн-оплати — замовлення лише фіксує намір купити, оплата й підтвердження — поза сайтом.
- Без резервування/списання складу — `in_stock` у таблицях товарів лишається таким, як є,
  замовлення його не змінює.
- Без валідації телефону/адреси НП проти зовнішніх довідників — прості текстові поля.
- Кнопки Telegram-CTA в секції "Шиномонтаж"/"Акумулятори" (`render-service.ts`) не чіпаються —
  там немає прайсу й концепції "товару", лишаються прямими посиланнями в Telegram, як і зараз.

## Архітектура

### Дані замовлення

Новий лист Google Таблиці `Замовлення`, колонки (у цьому порядку):

| колонка | приклад | опис |
|---|---|---|
| order_id | `ORD-1782934123456` | унікальний ID, генерується Apps Script (`ORD-` + timestamp) |
| timestamp | `2026-08-27 14:32:10` | час створення замовлення (серверний час Apps Script) |
| status | `Нове` / `Опрацьовано` | керується адмінкою |
| name | `Олена Коваль` | ім'я покупця |
| phone | `+380671234567` | телефон покупця |
| delivery_method | `Самовивіз` / `Нова Пошта` | |
| np_city | `Кривий Ріг` | тільки якщо delivery_method = Нова Пошта, інакше порожньо |
| np_branch | `Відділення №12` | адреса або номер відділення/поштомату, тільки для Нової Пошти |
| comment | `Зателефонуйте після 18:00` | необов'язковий |
| items | багаторядковий текст, один товар на рядок | `1. Michelin Primacy 205/55 R16 — 2 шт. × 2400 грн = 4800 грн` |
| total | `4800` | сума всіх позицій (число) |

`items`/`total` зберігаються як готовий текст/число, а не окремими колонками на товар — кількість
товарів у замовленні змінна, а лист має фіксовану ширину.

### Бекенд: розширення `admin/apps-script/Code.gs`

Той самий деплой Apps Script Web App, що вже обслуговує адмінку текстів (`CONTENT_API_URL` в
`src/config.ts`), отримує три нові дії в `doPost`:

- **`action: 'order'`** (публічна, без пароля — викликає сайт від імені будь-якого відвідувача):
  - payload: `{ name, phone, deliveryMethod, npCity?, npBranch?, comment?, items: [{title, sizeLine, price, qty}], total }`
  - генерує `order_id`, дописує рядок у лист `Замовлення` зі `status = 'Нове'`
  - формує текстове зведення замовлення (те саме, що йде і в колонку `items`, і в Telegram)
  - відправляє POST на Telegram Bot API (`https://api.telegram.org/bot<BOT_TOKEN>/sendMessage`)
    з `chat_id = CHAT_ID` і зведенням замовлення
  - **Telegram-запит обгорнутий у `try/catch`: якщо він падає (бот заблокований, немає мережі,
    невірний токен), помилка лише логується (`console.error`/`Logger.log`), сам запис у таблицю
    вже відбувся раніше і не відкочується.** Це і є вимога "таблиця — довга пам'ять" зі спеки.
  - завжди повертає `{ ok: true, orderId }`, якщо запис у таблицю вдався; `{ ok: false, error }`
    лише якщо не вдалось дописати рядок (напр. лист не існує і його не вдалось створити).
- **`action: 'listOrders'`** (потребує `password`, як і `save`):
  - повертає всі рядки листа `Замовлення` як масив об'єктів, найновіші можна сортувати на
    клієнті (сервер віддає в порядку рядків = порядку надходження)
- **`action: 'updateOrderStatus'`** (потребує `password`):
  - payload: `{ password, orderId, status }`
  - знаходить рядок за `order_id`, оновлює колонку `status`
  - повертає `{ ok: true }` / `{ ok: false, error }`, якщо `orderId` не знайдено

`BOT_TOKEN` і `CHAT_ID` зберігаються в тих самих Script Properties, що й `ADMIN_PASSWORD`
(Project Settings → Script Properties). Лист `Замовлення` створюється лінивою при першому виклику
`action: 'order'`, якщо ще не існує (за аналогією з тим, як `saveContentValue_` створює лист
"Контент").

### Клієнт: кошик

- **`src/js/cart.ts`** — модуль стану кошика:
  - тип позиції: `{ key, title, sizeLine, price, qty }`, де `key` — стабільний рядок-ідентифікатор
    товару (комбінація `idPrefix` + `title` + `sizeLine`), щоб повторне натискання "Купити" на той
    самий товар збільшувало `qty`, а не додавало дублікат
  - зберігання в `localStorage` (переживає перезавантаження сторінки; кошик — не сесійна річ)
  - API: `addItem()`, `updateQty()`, `removeItem()`, `clear()`, `getItems()`, `getTotal()`,
    `getCount()`, підписка `onChange(cb)` для оновлення бейджа й вмісту панелі без перезавантаження
- **`src/js/cart-ui.ts`** — бічна панель (drawer):
  - відкривається кліком на іконку кошика в хедері, закривається хрестиком/оверлеєм/Esc
  - список позицій з кнопками `+`/`−`/видалити й сумою; якщо кошик порожній — повідомлення
    "Кошик порожній"
  - нижче — форма оформлення: Ім'я, Телефон, радіо-вибір способу доставки (Самовивіз / Нова
    Пошта), умовні поля Місто + Відділення/адреса (з'являються тільки при виборі Нової Пошти),
    Коментар (необов'язково), кнопка "Оформити замовлення"
  - валідація по мінімуму: ім'я й телефон обов'язкові, поля НП обов'язкові лише якщо обрано
    доставку НП
  - по сабміту: POST `action: 'order'` на `CONTENT_API_URL`; поки триває запит — кнопка
    заблокована; при успіху — `cart.clear()`, панель показує підтвердження "Замовлення прийнято,
    ми з вами зв'яжемось" і за кілька секунд закривається; при мережевій помилці — повідомлення про
    помилку з можливістю повторити (кошик НЕ очищується, щоб не втратити дані)
- **Хедер** (`index.html`): іконка кошика з бейджем-лічильником додається в `.header-actions` (біля
  телефону, перед бургером); бейдж ховається, коли кошик порожній
- **`render-products.ts`**: кнопка "Купити" на картці товару більше не веде в Telegram — викликає
  `cart.addItem(...)`, показує короткий тост "Додано в кошик" (авто-зникає). Кнопка копіювання
  тексту прибирається — вона була фолбеком саме для прямого Telegram-переходу, якого тут більше
  немає на цьому кроці. `CardInfo.telegramMessage` більше не потрібен для товарних карток
  (замінюється полями, потрібними кошику: стабільний `key` і коротке `sizeLine` для відображення).

### Адмінка: вкладка "Замовлення"

- `admin/index.html` отримує перемикач вкладок: **"Замовлення" (перша, активна за замовчуванням)**
  і "Тексти" (друга) — той самий сеансовий пароль (`sessionStorage`), що й зараз, відкриває обидві
  вкладки одразу після входу.
- **`src/admin/orders.ts`** — нова вкладка:
  - при вході викликає `listOrders`, рендерить картки замовлень, найновіші зверху (сортування на
    клієнті за `timestamp`)
  - кожна картка показує всі поля замовлення (контакти, доставку, список товарів, суму, час,
    статус)
  - кнопка "Опрацьовано" на картках зі статусом "Нове" — по кліку викликає `updateOrderStatus`,
    після успіху картка одразу перемальовується зі статусом "Опрацьовано" і кнопка ховається
  - `src/admin/main.ts` переробляється на невеликий роутер вкладок, що викликає
    `initOrdersTab()`/`initContentTab()` залежно від активної вкладки; логіка password-гейта й
    `callApi` виноситься в спільний модуль (`src/admin/api.ts`), яким користуються обидві вкладки

## Обробка помилок

- `listOrders`/`updateOrderStatus` повертають `{ ok: false, error }` при проблемах — адмінка
  показує те саме спливаюче повідомлення про помилку, що вже є в `admin/main.ts` (`showStatus`)
- Якщо `CONTENT_API_URL` порожній (адмінка ще не задеплоєна) — і кошик, і вкладка "Замовлення"
  показують те саме повідомлення "не налаштовано", що вже показує `renderNotConfigured()`
- Помилка мережі при оформленні замовлення не втрачає дані кошика (див. вище)
- Помилка відправки в Telegram не блокує запис у таблицю (див. вище) — це основна гарантія
  "довгої пам'яті" зі спеки

## Тестування

- `npm run typecheck` — єдина автоматична перевірка в репо, має проходити після кожної зміни
- Ручна перевірка через `npm run dev` (проти демо-CSV): додати кілька товарів з обох каталогів у
  кошик, змінити кількість, оформити замовлення — перевірити локальний стан кошика й UI-потік
- Виклики Apps Script (`order`/`listOrders`/`updateOrderStatus`) неможливо перевірити локально без
  задеплоєного скрипта — це власник перевіряє вручну на реальній Google Таблиці й Telegram-боті
  після деплою (кроки — в оновленому `README.md`)

## Налаштування (одноразово, для власника)

Кроки додаються в `README.md` поруч з існуючою інструкцію про `ADMIN_PASSWORD`:

1. Створити бота через `@BotFather` в Telegram (`/newbot`), отримати `BOT_TOKEN`
2. Написати боту будь-яке повідомлення від акаунту власника, потім через
   `https://api.telegram.org/bot<TOKEN>/getUpdates` знайти свій `chat_id`
3. Project Settings → Script Properties → додати `BOT_TOKEN` і `CHAT_ID` (поруч з наявним
   `ADMIN_PASSWORD`)
4. Оновити деплой Web App (Deploy → Manage deployments → New version), URL лишається той самий,
   `CONTENT_API_URL` в `src/config.ts` міняти не потрібно

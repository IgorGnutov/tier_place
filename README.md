# TIRE PLACE — лендінг автомагазину (Кривий Ріг)

Односторінковий статичний сайт: Vite + vanilla TypeScript + чистий CSS, без бекенду.
Дані про шини, диски й прайс шиномонтажу тягнуться напряму з Google Sheets у форматі CSV.

## Стек і чому саме він

- **Vite + vanilla TypeScript** — нуль зайвого рантайму фреймворку, швидкий білд у статику,
  сумісний із GitHub Pages / Netlify / Cloudflare Pages без серверної частини.
- **Чистий CSS** (CSS Grid + Flexbox, змінні, `clamp()`) — без Bootstrap/Tailwind.
- **Papa Parse** — єдина легка залежність, потрібна для надійного парсингу CSV
  (лапки, коми в значеннях, `\r\n`, BOM), яких повний власноручний парсер напрошується
  на важкі важковловимі баги.
- **sharp** (dev-залежність) — генерація AVIF/WebP/JPEG у кількох розмірах для фото слайдера.

## Швидкий старт

```bash
npm install
npm run dev        # локальний розробницький сервер (Vite)
npm run build       # білд у dist/
npm run preview     # локальний перегляд зібраного dist/
npm run typecheck   # перевірка типів TypeScript
```

## Деплой

Сайт повністю статичний — після `npm run build` вміст папки `dist/` можна викласти куди завгодно:

- **GitHub Pages**: увімкнути Pages з гілки/екшена, що публікує вміст `dist/` (наприклад, через
  `actions/upload-pages-artifact` після кроку `npm run build`). `vite.config.ts` вже налаштований з
  `base: './'`, тому сайт коректно працює і в корені домену, і в підпапці репозиторію.
- **Netlify / Cloudflare Pages**: Build command `npm run build`, Publish directory `dist`.

## Структура проєкту

```
index.html               — розмітка сторінки, SEO-метатеги, JSON-LD
src/
  main.ts                — точка входу, ініціалізація всіх модулів
  config.ts               — URL Google Sheets, контакти, Telegram — єдине місце для правок
  styles/                  — variables.css + CSS по секціях, підключаються через main.css
  data/gallery.ts          — список слайдів hero-слайдера
  js/
    csv.ts                 — парсинг CSV (Papa Parse), нормалізація ціни/булевих значень
    sheets.ts               — завантаження CSV з кешем sessionStorage (5 хв) і фолбеком
    filters.ts               — залежні фільтри + синхронізація стану з URL
    render-products.ts       — каталог шин/дисків: фільтри, сортування, картки, "показати ще"
    render-service.ts        — прайс шиномонтажу з CSV (таблиця + картки для вузьких екранів)
    hero-slider.ts            — vanilla-слайдер (crossfade, автоплей, свайп, ARIA)
    nav.ts                     — бургер-меню, підсвітка активного пункту, тінь хедера
    telegram.ts                 — посилання на Telegram-заявку + копіювання в буфер
    map.ts                      — лінива вставка Google Maps iframe
data/*.csv                — демо-дані (фолбек, якщо Google Sheets недоступні)
assets/ → public/assets/  — фото магазину і логотип-плейсхолдер (див. нижче, чому в public/)
scripts/optimize-photos.mjs — генерація AVIF/WebP/JPEG у розмірах 480/768/1200/1920
public/                   — статичні файли, копіюються в dist/ як є (robots.txt, sitemap.xml,
                            favicon, manifest, а також assets/ і data/ — це важливо, див. нижче)
```

**Чому фото й demo-CSV лежать у `public/`, а не в `assets/`/`data/` в корені:** hero-слайдер
формує шляхи до файлів рядками (`${base}-${width}.${ext}`) у момент виконання JS, а не через
`import`. Vite вміє автоматично копіювати в білд лише ті файли, посилання на які може статично
проаналізувати (в HTML-атрибутах або через `import`) — рядки, зібрані на льоту в TypeScript, він
не бачить. Тому все, на що посилаються динамічно (фото слайдера, локальні CSV-фолбеки), лежить у
`public/`, звідки Vite копіює вміст у `dist/` без обробки, і шлях працює однаково для статичних і
динамічних посилань.

## Як додати або замінити фото в слайдері

1. Покладіть фото в `public/assets/photos/` з іменем виду
   `tire-place-kryvyi-rih-{shyny|dyski|akumulyatory|shynomontazh|vyviska}-N.jpg`
   (наприклад, `tire-place-kryvyi-rih-dyski-1.jpg`). Рекомендований розмір — 2000px по довгій
   стороні, орієнтація як знято (скрипт сам порахує пропорції).
2. Запустіть `npm run optimize:photos` — скрипт (`scripts/optimize-photos.mjs`, на sharp)
   згенерує AVIF/WebP/JPEG у розмірах 480/768/1200/1920px у `public/assets/photos/optimized/`
   (без апскейлу, якщо оригінал менший).
3. Додайте слайд у `src/data/gallery.ts`: `base` — ім'я файлу без розширення й без `-{width}`,
   `width`/`height` — розміри найбільшого згенерованого варіанта (дивіться вивід скрипта),
   `alt` — унікальний опис із гео-ключами (не "фото 1").
4. Перший слайд у масиві — це LCP-зображення: воно вже прописане прямо в `index.html` (реальний
   `<img>`, `eager`, `fetchpriority="high"`) для швидкого першого відображення. Якщо міняєте
   порядок і перший слайд стає іншим фото — оновіть і розмітку в `index.html` (блок
   `.hero__slide[data-slide-index="0"]`), і `<link rel="preload">` у `<head>`, щоб вони
   відповідали новому першому слайду.

**Юридично:** використовуйте лише фото, зроблені власником магазину (ті, що він завантажив
вручну). Фото відвідувачів з картки Google Maps використовувати не можна.

## Джерело даних: Google Sheets → CSV

Каталог шин, дисків і прайс шиномонтажу підтягуються з опублікованих Google-таблиць у форматі CSV
прямо в браузері. Поки посилання не налаштовані (або таблиця тимчасово недоступна/порожня) — сайт
автоматично показує демо-дані з `public/data/*.csv`, щоб нічого не виглядало зламаним.

### Як налаштувати свою таблицю

1. Створіть Google-таблицю (окрему на кожну категорію — шини, диски, шиномонтаж — або по вкладці
   на категорію в одному файлі, головне — правильний `gid` для export-посилання).
2. **Перший рядок — заголовки колонок, назви змінювати не можна** (сайт читає дані саме за цими
   ключами):
   - **Шини:** `group, brand, model, width, profile, diameter, season, studded, load_index, speed_index, price, currency, in_stock, image_url, note`
   - **Диски:** `group, brand, model, diameter, width, pcd, et, dia, type, color, price, currency, in_stock, image_url, note`
   - **Шиномонтаж:** `category, service, unit, price_r13_r14, price_r15_r16, price_r17_r18, price_r19_plus, note`
3. Надайте доступ **"Усі, хто має посилання — Читач"** (Sharing → Anyone with the link → Viewer).
   Без цього браузер відвідувача не зможе завантажити CSV.
4. Отримайте посилання виду `https://docs.google.com/spreadsheets/d/ІД_ТАБЛИЦІ/edit`, візьміть
   з нього `ІД_ТАБЛИЦІ`. Якщо дані на іншій вкладці, а не першій — подивіться `gid=...` в URL
   таблиці, коли ця вкладка відкрита.
5. Впишіть ІД (і за потреби `gid`) у **`src/config.ts`** — функція `sheetCsvUrl(spreadsheetId, gid)`
   вже формує потрібний `export?format=csv&gid=...` URL. Порожній рядок у `SHEET_*_CSV` означає
   "використовувати тільки локальний demo CSV".
6. Зміни в клітинках таблиці підʼявляться на сайті автоматично (з затримкою до 5 хв — стільки
   тримається кеш у `sessionStorage`, щоб не бити по таблиці на кожен перехід між сторінками).

Значення в колонці `studded` (шипи) і `in_stock` (наявність) можна писати як
`так/ні`, `yes/no`, `true/false` або `+/-` — розпізнається все. Ціну можна писати з пробілами,
комами чи "грн" — normalize відбувається автоматично.

## Як додати товар чи послугу

Просто додайте рядок у відповідну Google-таблицю з тими ж колонками — верстку й фільтри
редагувати не потрібно, вони будуть перебудовані автоматично з нових унікальних значень.

## Як змінити контакти

Все в одному місці — **`src/config.ts`**, об'єкт `CONTACTS`: телефон, Telegram, Instagram,
адреса, координати, посилання на карту, графік роботи.

## Що лишилось заповнити власнику

- **Instagram** — зараз посилання-заглушка `#` (позначено `<!-- TODO -->` в `index.html`).
  Замінити `href="#"` на реальний профіль у двох місцях — блок «Контакти» і футер — та оновити
  `CONTACTS.instagramUrl` в `src/config.ts`.
- **Графік роботи** — зараз orієнтовний ("Щодня, 9:00–19:00, графік уточнюється"), позначено
  `<!-- TODO -->` в `index.html` (`#hours-note`) і `CONTACTS.hoursNote` в `config.ts`.
- **Фото для слайдера** — додано 2 з 5–7 рекомендованих слотів (вивіска, стелаж із шинами).
  Бракує фото дисків, акумуляторів і зони шиномонтажу — інструкція вище.
- **Google Sheets** — таблиці для шин, дисків і прайсу шиномонтажу підключені й наповнені даними.
- **Домен** — у `index.html` (canonical, OG/Twitter-теги, JSON-LD) і в `public/robots.txt`/
  `public/sitemap.xml` зараз стоїть плейсхолдер `https://tireplace.com.ua/` — замінити на реальний
  домен, коли він буде визначений.
- **Google Business Profile, відгуки** — див. чекліст у `SEO.md`.

## Обмеження, про які варто знати

- Кнопка "Купити" веде в Telegram із передзаповненим текстом через `?text=` — це не в усіх
  клієнтах Telegram працює однаково надійно для приватних чатів, тому поруч є кнопка
  "скопіювати запит" (копіює той самий текст у буфер обміну) як підстраховка.
- Якщо жива Google-таблиця відповідає, але в ній 0 рядків з даними (порожня/ще не заповнена) —
  сайт трактує це так само, як недоступність, і показує demo-дані з позначкою в лічильнику
  "(показано демо-дані, таблиця тимчасово недоступна)", щоб розділ каталогу не виглядав порожнім
  під час налаштування.

# RU-локалізація (SEO-only) — дизайн

Дата: 2026-08-28

## Мета

Додати російськомовну версію сайту виключно для SEO-охоплення (частина аудиторії
Кривого Рогу шукає російською). Українська лишається основною/дефолтною мовою для
всіх відвідувачів. Перемикач мови в хедері — малопомітний. Назви товарів (бренд +
модель) і будь-які інші значення з Google-таблиць (сезон, тип, колір тощо) НЕ
перекладаються — лишаються такими, якими їх ввів власник у таблицю.

## Чому не просто клієнтський перемикач

Сайт — SPA без роутингу й без SSR: один `index.html`, весь контент рендериться в
браузері. Якщо мова перемикається лише в JS без зміни URL, Google завжди бачитиме
(і індексуватиме) той самий, дефолтний UA-стан — RU-текст ніколи не потрапить у
видачу. Тому мова прив'язана до URL query-параметра `?lang=ru`, з `hreflang` для
явного зв'язку між двома мовними варіантами однієї сторінки.

## Архітектура

### 1. `src/js/i18n.ts` (нове)

- `type Lang = 'uk' | 'ru'`
- `getLang(): Lang` — читає `?lang=ru` з `window.location.search`; будь-що інше →
  `'uk'`. Без збереження в localStorage/sessionStorage — українська завжди дефолт
  для нового заходу на сайт незалежно від попередніх візитів.
- `t(key: string, ukFallback: string): string` — для `'ru'` повертає
  `RU_STRINGS[key] ?? ukFallback`; для `'uk'` завжди повертає `ukFallback`.
  Використовується у JS-рендерерах (картки товарів, кошик, фільтри) — українська
  рядок лишається інлайн у коді як і зараз, тільки RU-переклад виноситься в словник.
- `applyStaticTranslations(): void` — для `lang === 'ru'` проходить по:
  - `[data-i18n]` → `el.textContent = RU_STRINGS[key] ?? залишити як є`
  - `[data-i18n-html]` → те саме, але `innerHTML` (для елементів із вкладеною
    розміткою, напр. `<span class="accent">`)
  - `[data-i18n-attr]` → міні-DSL `"aria-label:key1;placeholder:key2;content:key3"`,
    перекладає перелічені атрибути.
  Для `lang === 'uk'` — нічого не робить (HTML вже українською статично).
- `applyContentRegistryTranslations(): void` — окремий прохід по
  `[data-content-key]` для `lang === 'ru'`, підставляє `CONTENT_RU[key]` (бекап,
  якщо в Sheet нема `value_ru`). Викликається ДО `initContent()` у `main.ts`, щоб
  sheet-дані (якщо є) могли перезаписати цей бейзлайн — той самий порядок
  пріоритету, що вже є для UA (хардкод в HTML → Sheet override).
- `updateHeadForLang(): void`:
  - `document.documentElement.lang = lang`
  - `<title>` — теж отримує `data-i18n`, обробляється тим самим
    `applyStaticTranslations` (textContent працює і для `<title>`).
  - `<meta name="description">`, OG (`og:title`, `og:description`, `og:locale`),
    Twitter (`twitter:title`, `twitter:description`) — отримують
    `data-i18n-attr="content:meta.xxx"` і перекладаються через загальний механізм.
  - `<link rel="canonical">` — переписується на `.../` (uk) або `.../?lang=ru` (ru)
    через `id="canonical-link"` + прямий `href`-виклик (не рядковий переклад, а URL
    з поточного origin/pathname).
- `initLangSwitch(): void` — навішує обробники на `[data-lang-link]`:
  `preventDefault()`, `history.pushState` з новим `?lang=` (зберігаючи поточний
  `#hash` і всі інші query-параметри — `tires_*`/`wheels_*` фільтри), потім
  повторний виклик усього ланцюжка перекладу (без перезавантаження сторінки).
  `href` обох посилань оновлюється при кожному виклику, щоб завжди вести на
  коректний URL (для випадку без JS / для сканування ботом).
- `initI18n(): void` — оркеструє все вище, викликається першою в `main.ts` (до
  `initContent()`, до рендеру каталогів/кошика — щоб `t()` у них уже бачив
  правильну мову).

### 2. `src/i18n/strings.ts` (нове) — `RU_STRINGS: Record<string, string>`

Плаский словник ключ → RU-рядок. Ключі відповідають:
- `nav.*` (Шини/Диски/Шиномонтаж/Акумулятори/Контакти + footer-nav дублікат)
- `hero.*` (H1 лишається "TIRE PLACE" — власна назва, не перекладається; trust-list,
  CTA-кнопки)
- `catalog.*` (таби "Шини"/"Диски", лейбли фільтрів — Ширина/Профіль/Діаметр/Сезон/
  Шипи/Бренд/Ціна, плейсхолдери "Будь-який"/"Будь-яка"/"Не важливо"/"від"/"до",
  сортування, "Скинути фільтр", "Показати ще", "Завантаження…", "Знайдено: N",
  "Нічого не знайдено…")
- `product.*` (специфікації карток — Сезон/Шипи/Так/Ні/Індекс навантаження/Індекс
  швидкості/Тип/PCD/ET/DIA/Колір, "В наявності"/"Немає в наявності", "Купити",
  "Ціна за запитом")
- `service.*`, `battery.*` — заголовки секцій, перки, кнопки
- `contacts.*` — лейбли (Телефон/Адреса/Графік роботи/Ми в соцмережах), кнопки
  карти
- `faq.*` — самі питання (`<summary>`) — відповіді йдуть через content-registry шар
- `cart.*` — увесь кошик і форма чекауту (заголовки, лейбли полів, "Самовивіз з
  магазину"/"Нова Пошта", помилки валідації, підтвердження замовлення, toast-и)
- `footer.*` — таглайн-дублікат (як фолбек, якщо Sheet порожній), "Всі права
  захищені"
- `meta.*` — title/description/OG/Twitter
- `a11y.*` — aria-label-и (кошик, бургер, стрілки слайдера, play/pause, "Прибрати
  фільтр X" — параметризовані через просту підстановку `{label}`)

Українські рядки НЕ дублюються в окремому UK-словнику — вони лишаються
захардкоджені в HTML/TS, як і зараз; RU_STRINGS — це тільки шар-оверрайд.

### 3. Контент-блоки з `/admin` (`CONTENT_REGISTRY`)

- `src/admin/content-registry.ts`: кожен `ContentBlock` отримує `defaultHtmlRu:
  string` — реальний, зв'язний переклад поточного `defaultHtml` (не заглушка).
- `src/js/content.ts` (`initContent`): при `lang === 'ru'` бере `row.value_ru` з
  CSV, якщо воно непорожнє; інакше — фолбек на `row.value` (UA-текст із Sheet, якщо
  власник ще не переклав); інакше — на хардкод (через уже застосований
  `applyContentRegistryTranslations()`, який виконався раніше й підставив
  `defaultHtmlRu`).
- **`/admin` UI (`content-tab.ts`, `admin/apps-script/Code.gs`) НЕ змінюється** —
  за вашою вказівкою. Колонку `value_ru` власник за потреби заповнює вручну
  напряму в Google Таблиці; редактор Quill у `/admin` продовжує показувати й
  зберігати лише UA `value`, як зараз.
- `public/data/content.csv` (локальний фолбек) — додається порожня колонка
  `value_ru` в заголовок для консистентності схеми (дані лишаються порожні, як і
  зараз).

### 4. `index.html`

- Додаються статичні `<link rel="alternate" hreflang="uk" href=".../">`,
  `hreflang="ru" href=".../?lang=ru">`, `hreflang="x-default" href=".../">` в
  `<head>` (завжди присутні обидва, незалежно від поточної мови сторінки).
- `<link rel="canonical" id="canonical-link">` — id додається для JS-оновлення.
- `<title>`, `<meta name="description">`, OG/Twitter теги отримують
  `data-i18n`/`data-i18n-attr`.
- Усі текстові вузли з переліку словника (§2) отримують `data-i18n` /
  `data-i18n-html` / `data-i18n-attr`.
- Перемикач мови в `.header-actions`, поруч із телефоном/кошиком:
  ```html
  <div class="lang-switch" aria-label="Мова сайту">
    <a href="?lang=uk" class="lang-switch__link" data-lang-link="uk">UA</a><span aria-hidden="true">/</span><a href="?lang=ru" class="lang-switch__link" data-lang-link="ru">RU</a>
  </div>
  ```
  Стилі — маленький текст, приглушений колір, активна мова трохи виділена вагою/
  кольором, неактивна — тьмяніша й підкреслюється лише на hover. Без прапорів
  (нейтральний текстовий лейбл, не привертає зайвої уваги).
- JSON-LD `<script>` блоки — без змін (лишаються UA, задокументовано як свідоме
  обмеження скоупу).

### 5. Реренд при перемиканні

Оскільки `initCatalogs()`, `initContent()`, `initCart()` тощо вже виконались один
раз при завантаженні, а `t()`-виклики "заморожені" в уже відрендерених DOM-вузлах
(картки товарів, кошик), клік по перемикачу мови має:
1. Оновити `lang` (URL + внутрішній стан).
2. Викликати `applyStaticTranslations()` + `applyContentRegistryTranslations()` +
   `updateHeadForLang()` заново (дешево, це просто textContent/attr-заміни).
3. Для каталогів/кошика — оскільки їхній HTML генерується функціями
   (`renderCard`, `renderItemsList`, `buildCheckoutForm`), які вже викликають
   `t()` у момент рендеру, найпростіший і найнадійніший спосіб — **перерендерити
   їх** (`renderResults()` для активного табу, `renderBody()` для кошика) замість
   точкового патчингу DOM. Це недорого (дані вже в пам'яті, мережевий запит не
   повторюється) і уникає розсинхрону "напівперекладеного" стану.
   Реалізація: `i18n.ts` експортує підписку `onLangChange(cb)`, на яку
   `render-products.ts` і `cart-ui.ts` підписуються під час ініціалізації і
   викликають свій наявний рендер-метод повторно.

### 6. `sitemap.xml`

Додається другий `<url>` запис для `https://tireplace.com.ua/?lang=ru` з
`xhtml:link rel="alternate" hreflang` анотаціями на обидва записи (взаємне
посилання uk↔ru), за прикладом Google's sitemap hreflang extension.

## Явні межі скоупу (свідомо не робимо)

1. **JSON-LD не перекладається** (5 блоків: AutoPartsStore/Service/FAQPage/
   BreadcrumbList) — лишається українською. Можливий неспівпад мови видимого
   тексту й структурованих даних Google толерує; дублювання 5 блоків двома мовами
   визнано непропорційним обсягом для цього завдання.
2. **Значення з Google-таблиць (Шини/Диски CSV)** — бренд, модель, сезон, тип,
   колір тощо — НЕ перекладаються, лишаються мовою, якою їх ввів власник таблиці.
3. **`/admin` інтерфейс** — жодних змін, лишається повністю українським; RU-текст
   контент-блоків керується виключно прямим редагуванням колонки `value_ru` в
   Google Таблиці власником (поза кодом/адмінкою).
4. Домен `tireplace.com.ua` — і далі плейсхолдер (як і в решті SEO-тегів, за
   `SEO.md`); hreflang/canonical/sitemap-URL для RU будуються на тому самому
   плейсхолдері, синхронно з існуючими UA-тегами.

## Тестування

- `npm run typecheck` — має проходити без помилок.
- Ручна перевірка в `npm run dev`:
  - Дефолтне завантаження (`/`) — все українською, перемикач показує UA активним.
  - Клік на "RU" → URL стає `?lang=ru` (без перезавантаження), весь текст
    (хедер/hero/каталог/фільтри/шиномонтаж/акумулятори/контакти/FAQ/футер/кошик)
    перемикається, `<html lang>` = `ru`, `<title>`/meta-description змінились,
    canonical вказує на `?lang=ru`.
  - Пряме відкриття `/?lang=ru` (як робив би Googlebot) — одразу рендериться
    російською, без миготіння українською.
  - Перемикання назад на UA — усе повертається, включно з уже відкритим кошиком/
    заповненою формою чекауту (дані форми не губляться при перерендері —
    використовується наявний механізм `persistDraft`/`restoreCheckoutDraft`).
  - Фільтри каталогу (`tires_brand=...` тощо) і `#hash`-секція зберігаються при
    перемиканні мови.
  - Назви товарів (бренд/модель) і значення полів з таблиці лишаються
    незмінними в обох мовах.
  - `view-source:` перевірка — `hreflang`-теги присутні в статичному HTML без
    виконання JS.

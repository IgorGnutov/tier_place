# TIRE PLACE — лендінг автомагазину (Кривий Ріг)

Односторінковий статичний сайт: Vite + vanilla TypeScript + чистий CSS, без бекенду.
Дані про шини й диски тягнуться напряму з Google Sheets у форматі CSV.

## Стек і чому саме він

- **Vite + vanilla TypeScript** — нуль зайвого рантайму фреймворку, швидкий білд у статику,
  сумісний із GitHub Pages / Netlify / Cloudflare Pages без серверної частини.
- **Чистий CSS** (CSS Grid + Flexbox, змінні, `clamp()`) — без Bootstrap/Tailwind.
- **Papa Parse** — єдина легка залежність, потрібна для надійного парсингу CSV
  (лапки, коми в значеннях, `\r\n`, BOM), яких повний власноручний парсер напрошується
  на важкі важковловимі баги.
- **sharp** (dev-залежність) — генерація AVIF/WebP/JPEG у кількох розмірах для фото слайдера.

## Швидкий старт

```bash
npm install
npm run dev        # локальний розробницький сервер (Vite)
npm run build       # білд у dist/
npm run preview     # локальний перегляд зібраного dist/
npm run typecheck   # перевірка типів TypeScript
```

## Деплой

Сайт повністю статичний — після `npm run build` вміст папки `dist/` можна викласти куди завгодно.
`vite.config.ts` налаштований з `base: './'`, тому сайт коректно працює і в корені домену, і в
підпапці репозиторію.

**Поточний деплой — GitHub Actions → власний хостинг по FTP**
(`.github/workflows/deploy.yml`): кожен push у `main` збирає проєкт і заливає вміст `dist/` на
хостинг через `SamKirkland/FTP-Deploy-Action` (протокол `ftp`). Потрібні GitHub Secrets
(Settings → Secrets and variables → Actions):

| Secret            | Значення                                                                 |
|-------------------|---------------------------------------------------------------------------|
| `FTP_SERVER`      | хост FTP-сервера (панель хостингу → FTP → Користувачі FTP)                |
| `FTP_USERNAME`    | FTP-логін                                                                  |
| `FTP_PASSWORD`    | FTP-пароль                                                                 |
| `FTP_REMOTE_DIR`  | шлях до кореня сайту на хостингу (напр. `/tire-place.com.ua/public_html/`) |

Дія повністю синхронізує `FTP_REMOTE_DIR` з поточним `dist/` (видаляє файли на сервері, яких
немає в білді) — не тримайте там вручну завантажені файли, вони будуть видалені при наступному
деплої. Якщо хостинг підтримує шифрований FTPS і потрібна вища безпека — заміните `protocol: ftp`
на `protocol: ftps` у workflow (у нас на `ftps` `data socket` рвався з `ECONNRESET`, тому зараз
використовується звичайний `ftp`).

Альтернативи, якщо потрібно змінити спосіб деплою:
- **SSH/rsync**: `burnett01/rsync-deployments` — безпечніше за FTP (ключ замість пароля,
  шифрований канал), потребує робочого SSH-доступу з боку хостингу.
- **GitHub Pages**: `actions/upload-pages-artifact` + `actions/deploy-pages` після кроку `npm run build`.
- **Netlify / Cloudflare Pages**: Build command `npm run build`, Publish directory `dist`.

## Структура проєкту

```
index.html               — розмітка сторінки, SEO-метатеги, JSON-LD
admin/
  index.html               — окрема сторінка /admin (другий Vite-entry, не в публічному бандлі)
  apps-script/Code.gs       — скрипт для Google Apps Script (запис у лист "Контент" + перевірка пароля)
src/
  main.ts                — точка входу, ініціалізація всіх модулів
  config.ts               — URL Google Sheets, контакти, Telegram — єдине місце для правок
  styles/                  — variables.css + CSS по секціях, підключаються через main.css
                             (admin.css підключається окремо, лише сторінкою /admin)
  data/gallery.ts          — список слайдів hero-слайдера
  admin/
    main.ts                  — логіка /admin: пароль-гейт, список блоків, Quill-редактор, збереження
    content-registry.ts       — реєстр текстових блоків (key/label/group/дефолтний текст)
  js/
    csv.ts                 — парсинг CSV (Papa Parse), нормалізація ціни/булевих значень
    sheets.ts               — завантаження CSV з кешем sessionStorage (5 хв) і фолбеком
    content.ts               — підстановка відредагованих через /admin текстів у [data-content-key]
    filters.ts               — залежні фільтри + синхронізація стану з URL
    render-products.ts       — каталог шин/дисків: фільтри, сортування, картки, "показати ще"
    render-service.ts        — Telegram-посилання для кнопок запису на шиномонтаж/акумулятори
    hero-slider.ts            — vanilla-слайдер (crossfade, автоплей, свайп, ARIA)
    nav.ts                     — бургер-меню, підсвітка активного пункту, тінь хедера
    telegram.ts                 — спливаюче повідомлення (toast) унизу екрана
    map.ts                      — лінива вставка Google Maps iframe
data/*.csv                — демо-дані (фолбек, якщо Google Sheets недоступні)
assets/ → public/assets/  — фото магазину і логотип-плейсхолдер (див. нижче, чому в public/)
scripts/optimize-photos.mjs — генерація AVIF/WebP/JPEG у розмірах 480/768/1200/1920
public/                   — статичні файли, копіюються в dist/ як є (robots.txt, sitemap.xml,
                            favicon, manifest, а також assets/ і data/ — це важливо, див. нижче)
```

**Чому фото й demo-CSV лежать у `public/`, а не в `assets/`/`data/` в корені:** hero-слайдер
формує шляхи до файлів рядками (`${base}-${width}.${ext}`) у момент виконання JS, а не через
`import`. Vite вміє автоматично копіювати в білд лише ті файли, посилання на які може статично
проаналізувати (в HTML-атрибутах або через `import`) — рядки, зібрані на льоту в TypeScript, він
не бачить. Тому все, на що посилаються динамічно (фото слайдера, локальні CSV-фолбеки), лежить у
`public/`, звідки Vite копіює вміст у `dist/` без обробки, і шлях працює однаково для статичних і
динамічних посилань.

## Як додати або замінити фото в слайдері

1. Покладіть фото в `public/assets/photos/` з іменем виду
   `tire-place-kryvyi-rih-{shyny|dyski|akumulyatory|shynomontazh|vyviska}-N.jpg`
   (наприклад, `tire-place-kryvyi-rih-dyski-1.jpg`). Рекомендований розмір — 2000px по довгій
   стороні, орієнтація як знято (скрипт сам порахує пропорції).
2. Запустіть `npm run optimize:photos` — скрипт (`scripts/optimize-photos.mjs`, на sharp)
   згенерує AVIF/WebP/JPEG у розмірах 480/768/1200/1920px у `public/assets/photos/optimized/`
   (без апскейлу, якщо оригінал менший).
3. Додайте слайд у `src/data/gallery.ts`: `base` — ім'я файлу без розширення й без `-{width}`,
   `width`/`height` — розміри найбільшого згенерованого варіанта (дивіться вивід скрипта),
   `alt` — унікальний опис із гео-ключами (не "фото 1").
4. Перший слайд у масиві — це LCP-зображення: воно вже прописане прямо в `index.html` (реальний
   `<img>`, `eager`, `fetchpriority="high"`) для швидкого першого відображення. Якщо міняєте
   порядок і перший слайд стає іншим фото — оновіть і розмітку в `index.html` (блок
   `.hero__slide[data-slide-index="0"]`), і `<link rel="preload">` у `<head>`, щоб вони
   відповідали новому першому слайду.

**Юридично:** використовуйте лише фото, зроблені власником магазину (ті, що він завантажив
вручну). Фото відвідувачів з картки Google Maps використовувати не можна.

## Джерело даних: Google Sheets → CSV

Каталог шин і дисків підтягується з опублікованих Google-таблиць у форматі CSV прямо в браузері.
Поки посилання не налаштовані (або таблиця тимчасово недоступна/порожня) — сайт автоматично показує
демо-дані з `public/data/*.csv`, щоб нічого не виглядало зламаним.

### Як налаштувати свою таблицю

1. Створіть Google-таблицю (окрему на кожну категорію — шини, диски — або по вкладці на категорію
   в одному файлі, головне — правильний `gid` для export-посилання).
2. **Перший рядок — заголовки колонок, назви змінювати не можна** (сайт читає дані саме за цими
   ключами):
   - **Шини:** `group, brand, model, width, profile, diameter, season, studded, load_index, speed_index, year, country, price, currency, in_stock, image_url, note`
   - **Диски:** `group, brand, model, diameter, width, pcd, et, dia, type, color, price, currency, in_stock, image_url, note`
3. Надайте доступ **"Усі, хто має посилання — Читач"** (Sharing → Anyone with the link → Viewer).
   Без цього браузер відвідувача не зможе завантажити CSV.
4. Отримайте посилання виду `https://docs.google.com/spreadsheets/d/ІД_ТАБЛИЦІ/edit`, візьміть
   з нього `ІД_ТАБЛИЦІ`. Якщо дані на іншій вкладці, а не першій — подивіться `gid=...` в URL
   таблиці, коли ця вкладка відкрита.
5. Впишіть ІД і `gid` у **`src/data/sheet-ids.json`** — `src/config.ts` читає цей файл і функцією
   `sheetCsvUrl(spreadsheetId, gid)` формує потрібний `export?format=csv&gid=...` URL. Той самий
   JSON читає й білд-скрипт сторінок товару, тому ІД зберігаються саме там, а не в двох місцях.
   Порожній рядок у `SHEET_*_CSV` означає "використовувати тільки локальний demo CSV".
6. Зміни в клітинках таблиці підʼявляться на сайті автоматично (з затримкою до 5 хв — стільки
   тримається кеш у `sessionStorage`, щоб не бити по таблиці на кожен перехід між сторінками).

Значення в колонці `studded` (шипи) і `in_stock` (наявність) можна писати як
`так/ні`, `yes/no`, `true/false` або `+/-` — розпізнається все. Ціну можна писати з пробілами,
комами чи "грн" — normalize відбувається автоматично.

**Фото товару (`image_url`, обидві таблиці — "Шини" і "Диски"):** якщо клітинка порожня — картка
показує плейсхолдер "Фото немає", решта картки працює як завжди. Якщо заповнена — там має бути
**пряме посилання на файл зображення** (закінчується на `.jpg`/`.png`/... і відкривається сам у
собі, без інтерфейсу сайту навколо). Посилання виду `https://drive.google.com/file/d/ID/view` з
"Поділитися" в Google Drive **не підійде** — це посилання на сторінку перегляду, а не на сам файл;
для Google Drive потрібно перетворити його на `https://drive.google.com/uc?export=view&id=ID`
(той самий `ID` з посилання). Простіше — завантажити фото на будь-який хостинг картинок (Imgur
тощо) і взяти пряме посилання звідти.

## Адмінка: редагування текстових блоків (`/admin`)

Статичні тексти сайту (hero, вступні абзаци, перки шиномонтажу, футер, FAQ тощо — повний список у
`src/admin/content-registry.ts`) можна редагувати без розробника через `/admin`, без переверстки
й без деплою. Товарні дані (шини, диски) сюди не входять — вони й надалі редагуються напряму
в своїх Google-листах, як описано вище.

Механіка: кожен редагований блок в `index.html` має атрибут `data-content-key="…"`. Значення
тягнуться з листа "Контент" у тій самій Google Таблиці (той самий принцип, що й для
шин/дисків — `loadCsv` з кешем sessionStorage і фолбеком на `public/data/content.csv`).
Якщо лист ще не налаштований або для блоку немає рядка — просто лишається статичний текст з
`index.html`, сторінка не показує жодних попереджень.

Лист "Контент" може мати необов'язкову третю колонку `value_ru`. Коли сайт працює в RU-режимі
(шлях `/ru/`), заповнена клітинка `value_ru` перевизначає вбудований у код російський текст для
цього блоку. Якщо `value_ru` порожня, RU-версія бере значення спочатку з колонки `value`
(українська), якщо воно заповнене, а вже потім — з вбудованого в код RU-варіанта за замовчуванням.
Цю колонку редагують напряму в Google Таблиці — через `/admin` вона недоступна: адмінка завжди
показує й редагує лише українську колонку `value`.

Запис із `/admin` іде окремим шляхом — клієнтський JS не може безпечно писати в Google Sheets
напряму (потрібні креденшели), тож запис і перевірка пароля відбуваються через **Google Apps
Script Web App**, прив'язаний до тієї ж таблиці. Це безкоштовний сервіс Google, а не окремий
хостований бекенд.

### Одноразове налаштування

1. У тій самій Google Таблиці створіть лист з назвою **"Контент"** і заголовками в першому
   рядку: `key, value`.
2. Відкрийте **Розширення → Apps Script** у цій таблиці й вставте вміст файлу
   `admin/apps-script/Code.gs` (з цього репозиторію) замість дефолтного `Code.gs`.
3. **Project Settings** (⚙ зліва) → **Script Properties** → додайте властивість
   `ADMIN_PASSWORD` зі значенням — паролем для входу в `/admin`.
4. **Deploy → New deployment**, тип **Web app**: `Execute as: Me`, `Who has access: Anyone`.
   Скопіюйте URL, що закінчується на `/exec`.
5. У `src/config.ts` впишіть:
   - `CONTENT_API_URL` — URL з кроку 4;
   - `SHEET_CONTENT_CSV` — `sheetCsvUrl(ІД_ТАБЛИЦІ, gid)` для листа "Контент" (той самий `ІД_ТАБЛИЦІ`,
     що вже використовується для шин/дисків; `gid` листа — з URL таблиці, коли ця вкладка відкрита,
     як і для інших листів вище).
6. Переконайтесь, що доступ до таблиці лишається "Усі, хто має посилання — Читач" (для читання
   CSV публічним сайтом; на запис це не впливає — запис завжди йде через Apps Script з перевіркою
   пароля).

Після цього відкрийте `/admin`, увійдіть паролем і редагуйте блоки — кожен має кнопку
«Редагувати», яка відкриває rich text editor (Quill) із поточним текстом.

**Про рівень безпеки:** це один простий пароль без сесій/токенів/ролей — свідомо, для одного
власника сайту з низьким трафіком, а не enterprise-автентифікація. Пароль ніколи не потрапляє в
клієнтський бандл (звіряється лише на боці Apps Script), але немає rate-limit на спроби входу.

## Кошик і замовлення

Кнопка "Купити" на картці товару (шини/диски) додає товар у кошик (бічна панель, іконка в
хедері) замість прямого переходу в Telegram. У кошику покупець редагує кількість, заповнює форму
(ім'я, телефон, спосіб доставки — самовивіз або Нова Пошта з містом і відділенням/адресою,
необов'язковий коментар) і тисне "Оформити замовлення".

Замовлення записується в лист **"Замовлення"** тієї ж Google Таблиці (створюється автоматично при
першому замовленні) і одночасно дублюється повідомленням від Telegram-бота власнику — той самий
Apps Script Web App, що вже обслуговує `/admin` (`CONTENT_API_URL` в `src/config.ts`), обробляє
запис і відправку. Якщо Telegram-повідомлення з якоїсь причини не надійшло — замовлення однаково
є в таблиці й видно в `/admin` → вкладка "Замовлення" (перша й активна за замовчуванням після
входу), де є кнопка "Опрацьовано" для позначення виконаних замовлень і кнопка "Видалити" —
вона лише приховує замовлення зі списку в адмінці (ID зберігається в Script Properties
Apps Script), рядок у самій Google Таблиці не видаляється. Приховані замовлення видно в
"Архів" (кнопка справа над списком), звідки їх можна повернути кнопкою "Відновити".

⚠️ **Важливо: порядок викочування.** Оновлений `admin/apps-script/Code.gs` (з діями `order`,
`listOrders`, `updateOrderStatus`, `hideOrder`, `listArchivedOrders`, `restoreOrder`) треба
задеплоїти в живу Google Таблицю **до або одночасно** з викочуванням цієї версії сайту. Старого
прямого переходу в Telegram з картки товару більше немає взагалі, тому поки Code.gs не
перезадеплоєний, кожна спроба оформити замовлення падатиме з повідомленням у стилі
`{"error":"Невідома дія"}` — і замовити товар буде неможливо. Ту саму помилку побачите й при
спробі видалити/відновити замовлення в адмінці, якщо задеплоєна версія Apps Script старіша за ці
дії — розгорніть нову версію (Deploy → Manage deployments → edit → New version → Deploy).

### Одноразове налаштування бота

1. У Telegram напишіть **@BotFather** → `/newbot`, дайте боту ім'я й унікальний username, що
   закінчується на `bot`. BotFather надішле **BOT_TOKEN** (`123456789:AA...`).
2. Знайдіть бота за його username і напишіть йому будь-яке повідомлення (бот не може написати
   першим).
3. Відкрийте в браузері `https://api.telegram.org/bot<BOT_TOKEN>/getUpdates` — у відповіді
   знайдіть `"chat":{"id": ЧИСЛО}` — це **CHAT_ID**.
4. Project Settings → Script Properties у тому ж Apps Script, що й `ADMIN_PASSWORD` — додайте
   `BOT_TOKEN` і `CHAT_ID`.
5. Deploy → Manage deployments → New version (URL лишається той самий, `CONTENT_API_URL` міняти
   не потрібно).

**Порада з безпеки:** токен бота дає повний контроль над ботом — не публікуйте його й не діліться
скріншотами з ним; якщо токен випадково "засвітився", перегенеруйте його через
`@BotFather → /mybots → обрати бота → API Token → Revoke current token`.

## Оновити товари поза розкладом

Сторінки товару (`/tires/<slug>/`, `/wheels/<slug>/`) перегенеровуються автоматично при кожному
пуші в `main` і кожні 6 годин за розкладом (GitHub Actions). Щоб не чекати — у `/admin` є кнопка
**"Оновити товари зараз"**, яка запускає той самий деплой одразу.

### Одноразове налаштування

1. Створіть fine-grained Personal Access Token: GitHub → Settings → Developer settings →
   Personal access tokens → Fine-grained tokens → New token. Обмежте його лише цим репозиторієм і
   дайте право **Actions: Read and write**.
2. У тому самому Apps Script (Project Settings → Script Properties), де вже є `ADMIN_PASSWORD`,
   `BOT_TOKEN`, `CHAT_ID` — додайте:
   - `GITHUB_TOKEN` — токен з кроку 1;
   - `GITHUB_REPO` — `власник/репозиторій`, напр. `IgorGnutov/tire_place`.
3. Deploy → Manage deployments → New version (URL лишається той самий).

**Порада з безпеки:** токен дає лише право запускати Actions цього репозиторію (не читання/запис
коду) — але все одно тримайте його в секреті так само, як `BOT_TOKEN`.

## Як додати товар чи послугу

Просто додайте рядок у відповідну Google-таблицю з тими ж колонками — верстку й фільтри
редагувати не потрібно, вони будуть перебудовані автоматично з нових унікальних значень.

**Увага: у кожного товару є власна постійна адреса.** Під час білда кожен рядок таблиці отримує
окрему сторінку — `/tires/<slug>/` або `/wheels/<slug>/` — і саме її бачать Google і прев'ю
посилань у Telegram/Facebook. `slug` рахується автоматично з колонок самого рядка: для шин це
`brand`, `model`, `width`, `profile`, `diameter`, `season`, для дисків — `brand`, `model`,
`diameter`, `width`, `pcd`, `et` (наприклад,
`/tires/hankook-winter-i-cept-iz3-w636-185-60-r15-zyma/`).

Тому **перейменування бренду чи моделі в уже наявному рядку змінює адресу сторінки цього товару**:
стара адреса перестає працювати, а разом з нею — уже розшарені посилання й позиція в Google
(доведеться чекати переіндексації). Виправляти дрібні одруківки в назвах — нормально, але робіть це
свідомо. Якщо рядок узагалі без бренду/моделі/розміру — сторінка для нього не створюється (у логах
білда буде попередження), а картка в каталозі просто лишиться без посилання.

## Як змінити контакти

Все в одному місці — **`src/config.ts`**, об'єкт `CONTACTS`: телефон, Telegram,
адреса, координати, посилання на карту, графік роботи.

## Що лишилось заповнити власнику

- **Графік роботи** — зараз orієнтовний ("Щодня, 9:00–19:00, графік уточнюється"), позначено
  `<!-- TODO -->` в `index.html` (`#hours-note`) і `CONTACTS.hoursNote` в `config.ts`.
- **Фото для слайдера** — додано 2 з 5–7 рекомендованих слотів (вивіска, стелаж із шинами).
  Бракує фото дисків, акумуляторів і зони шиномонтажу — інструкція вище.
- **Google Sheets** — таблиці для шин і дисків підключені й наповнені даними.
- **Адмінка `/admin`** — поки не задеплоєна (`CONTENT_API_URL` в `src/config.ts` порожній) —
  кроки налаштування вище, розділ "Адмінка: редагування текстових блоків".
- **Домен** — `https://tire-place.com.ua/` проставлено в `index.html` (canonical, OG/Twitter-теги,
  JSON-LD), `public/robots.txt` і `public/sitemap.xml`.
- **Google Business Profile, відгуки** — див. чекліст у `SEO.md`.

## Обмеження, про які варто знати

- Кнопки "Записатися" на шиномонтаж та підбір акумулятора (розділи "Шиномонтаж"/"Акумулятори")
  ведуть у Telegram із передзаповненим текстом через `?text=` — це не в усіх клієнтах Telegram
  працює однаково надійно для приватних чатів, тому в частини користувачів чат відкриється з
  порожнім полем вводу й текст доведеться написати самому. Кнопка "Купити" на картках товарів
  (шини/диски) працює інакше: вона додає товар у кошик замість прямого переходу в Telegram,
  див. розділ "Кошик і замовлення" вище.
- Якщо жива Google-таблиця відповідає, але в ній 0 рядків з даними (порожня/ще не заповнена) —
  сайт трактує це так само, як недоступність, і показує demo-дані з позначкою в лічильнику
  "(показано демо-дані, таблиця тимчасово недоступна)", щоб розділ каталогу не виглядав порожнім
  під час налаштування.
